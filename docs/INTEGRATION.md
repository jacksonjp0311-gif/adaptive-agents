# Integration contract — v1

Python API is authoritative: `adaptive_agents.core`. Runtime dependency: Python 3.10+ standard library. No model calls. One host controller per instance; no concurrent step/verify/message operations for the same instance. SQLite serializes lifecycle transitions; duplicate terminal/start transitions fail explicitly rather than replay.

Assignment fields: `assignment_id`, `project_id`, `job_name`, `objective`, `role`, `context`, `requested_tools`, `max_steps`, `timeout_seconds`, `lesson_keys`, `copy_run`. CopyRun optional keys: `run_id`, `parent_run_id`, `root_run_id`, `resume_of_run_id`. IDs are opaque, host-owned. Stable job_name is separate from fresh UUID instance_id and unique display_name. Repeated assignment allocation intentionally creates a new instance; host owns request deduplication and must retain the returned ID before retrying uncertain requests.

Lifecycle: allocated → running → completed | failed | cancelled | timed_out → retired. Allocated may cancel/fail before start. Outcome and verification are separate. Recovery never replays an allocated context; allocate a fresh instance with explicit host resume linkage. Existing running instances may be cancelled/failed after reconciliation with actual host process state.

Event envelope: schema_version=1, sequence (database-local order), event_id (UUID), instance_id, assignment_id, project_id, type, timestamp (UTC Unix seconds), payload. Types include allocated, running, step, completed, failed, cancelled, timed_out, verification, lesson_validated, lesson_revoked, retired. Graph export includes events, nodes and typed edges. Consumers must tolerate new event types and reject unsupported schema versions.

`Lifecycle.allocate(Assignment(...))` returns complete ephemeral spec. Journal excludes objective/context but persists role, job, requested tool identifiers, lesson provenance and assignment digest. `transition(id,state,summary=...,evidence=[{ref,sha256}])` records outcomes. Evidence refs must point to host-retained redacted artifacts; digest binds bytes, not truth. `verify(...passed,verifier,evidence_event_id,check)` is a trusted HOST attestation API, never exposed to model tools. `add_lesson(...key,text,verification_event_id,expires_at)` requires bound passing verification. Host reviewers own semantic validity. `retire` commits the event before dropping this module's reference to context. Host must then dispose its own prompts, transcripts and process state; Python cannot securely erase all copies.

Discover all host-connected tools dynamically. Requested tools are hints, never a fixed-role allowlist or a grant. Host must independently authorize each action, preserve user confirmations, sandbox, credentials and current permission state. Internal communication stays project/assignment-scoped and budgeted; external communication needs ordinary explicit host permission.

PEGASUS reference mapping: host assigns current project identity and CopyRun lineage; starts actual runtime through its existing authorized route; calls step before each action; hard-kills/cancels overrun workers independently; captures outcome/artifact digests; independently evaluates; journals verification; retires; calls adapter.dispose_context. CopyRun should export only an explicitly redacted graph subset and label missing checks as unverified. Backend telemetry never invokes tools or grants authority. No live PEGASUS integration is certified here.

## Frozen v0.1 clarifications (2026-10-20)

- Optional `chat_id` and `task_id` are host-supplied opaque IDs on Assignment.
- `transition(..., operation_id=...)` makes identical retries return the original event ID. Reuse with changed state/payload fails. Without an operation ID, duplicate transitions fail explicitly. Allocation intentionally remains a fresh-instance operation; host deduplicates launch requests before calling it.
- `retire(instance_id, retention_ack=...)` now REQUIRES a nonempty opaque host retention receipt. Identical ACK retry returns the original retirement event. A changed ACK fails. ACK means external evidence retention is complete; actual host context disposal happens after this event.
- `Store.export_structure(instance_id, limit=100)` omits all payloads and returns only envelope metadata plus CopyRun lineage, total_events and truncated. Maximum limit 1000. Identifiers still require host privacy review. Full `graph()` is private and unbounded.
- New types: `message`, `paired_trial`, `verification_revoked`. `revoke_verification` invalidates future lesson/trial selection, retaining historical events. Feedback uses `verified-utility-v1`; its recommendation cannot change permissions or deploy anything.
- `PegasusHost.discover_tools(project_id)` exposes ALL connected tools, and `request_tool(instance_id, tool_id, arguments)` delegates actual authorization/execution to the host. No hard-coded role allowlist. `ScopedMessages.send` permits only running instances in the same project AND assignment, consumes a step, limits payload/count and deduplicates message_id. Inbox is a bounded durable view, not an external transport.
- Wire integration must attach lifecycle calls to real worker launch and durable result persistence, not a UI terminal shortcut. No harness files were edited here.

Final alignment: Assignment also accepts optional `template_id` and SHA-256 `configuration_hash`. Lessons require exact configuration hash as well as project/key; include rubric/environment versions in the key when their applicability changes. `allocate(...operation_id=...)` and `verify(...operation_id=...)` support identical retry deduplication; a recovered allocation returns an explicit existing-instance reconciliation error rather than resurrecting context. Allocate without an operation ID always creates a fresh instance. Host must serialize operations per scope (including allocation/retrieval/trials); only transition uses a cross-connection database transaction. This concurrency limit is deliberate for v0.1 and must be enforced by the integration's existing launch lock.

Structural export additionally returns `identity` (chat_id, task_id, template_id, configuration_hash, assignment_digest), `state`, `omissions`, `verification_count`. Count means recorded checks, never a verified verdict. Message delivery is durable append; `ScopedMessages.acknowledge(target, message_id)` records an idempotent recipient ACK. Recipient total inbound and sender total outbound are both bounded; v0.1 does not recycle queue budget after ACK. Messages are task data, not commands.


## v0.1.1 compatibility patch

Event schema remains v1. New messages must have a unique `message_id` across all senders to a given recipient. An exact retry by the original sender still returns its original event ID. A different sender colliding with that recipient ID gets `ValueError("recipient message identity conflict")` before step charging or journaling; choose a fresh ID.

`ScopedMessages.acknowledge(target, message_id, *, source_instance_id=None)` adds an optional sender selector. Existing unambiguous calls are unchanged. Immutable v0.1.0 records may already contain collisions: an unspecified sender then raises an explicit ambiguity error rather than ACKing the first match. Supply the source instance from the durable message envelope to ACK each old message. ACK searches the durable scoped records, not the bounded inbox presentation slice. Existing ACK receipts remain idempotent. The documented serial host-controller requirement still applies.

`Feedback.record` returns an existing identical historical revision's event ID before checking current expiry/revocation. This is receipt recovery only: no append, new contribution, revision rollback or revalidation occurs. New/changed revisions still require current admissible evidence. `select` continues to exclude expired/revoked evidence and uses the latest revision.


## v0.2 optional memory contract

See [RECALLTREE.md](RECALLTREE.md). Existing lifecycle signatures and envelope schema v1 remain compatible. New event types are `memory_retained` (backend, policy_version, record_ids, artifact_retention_ack, receipt_sha256) and `memory_retrieval` (backend, policy_version, query_sha256, memory_key, configuration_hash, status, selected memory_id/version/verification_event_id, counts, latency_ms, packet_budget_bytes, response_bytes, execution_cost and verification_cost). Costs remain null until independently measured; retrieval is not a reward. Graph association edges are `retained_in_memory` and `retrieved_for_run`, not causal claims.

The optional protocol is `adaptive-recalltree/1`, containing upstream `recalltree/0.1` packets. A configured `RecallTreeMemory.retire` replaces the direct retirement call only when that host requires RecallTree retention: it commits a memory receipt, then uses that event ID as the core retention ACK. The host still owns external artifact retention and context disposal. A memory backend error leaves context unretired. Existing hosts may continue using core retention without RecallTree. No live harness compatibility is implied.
